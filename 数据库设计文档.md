# 电商智能售后中台 — 数据库设计文档

## 一、架构选型说明

| 存储 | 用途 | 核心表/结构 |
|---|---|---|
| **MySQL** | 业务主库：工单、店铺、订单、配置、日志 | `after_sale_order` / `store_info` / `order_info` / `system_config` / `operation_log` |
| **PostgreSQL + pgvector** | RAG 向量库：文本切片向量存储 + 相似度检索（由 langchain4j `PgVectorEmbeddingStore` 自动管理） | `rag_vectors` |
| **Redis** | 缓存加速、限流计数、ZSet 排行、分布式锁 | Key-Value / ZSet / Rate Limiter |

### 2.1 店铺信息表（store_info）

### 2.3 售后工单表（after_sale_order）⭐ 核心表

```sql
CREATE TABLE after_sale_order (
    id                  BIGINT AUTO_INCREMENT PRIMARY KEY,
    ticket_no           VARCHAR(32)     NOT NULL COMMENT '工单号，如 SH20260605001',

    -- 关联信息
    order_id            BIGINT          NOT NULL COMMENT '关联订单ID',
    order_no            VARCHAR(32)     NOT NULL COMMENT '关联订单号',
    store_id            BIGINT          NOT NULL COMMENT '店铺ID',
    user_id             BIGINT          NOT NULL COMMENT '用户ID',

    -- 售后内容
    after_sale_type     TINYINT         NOT NULL COMMENT '售后类型：1仅退款 2退货退款 3投诉',
    apply_reason        VARCHAR(1024)   NOT NULL COMMENT '申请原因',
    evidence_images     VARCHAR(2048)   DEFAULT '' COMMENT '凭证图片，JSON数组存储',
    apply_amount        DECIMAL(12,2)   DEFAULT 0.00 COMMENT '申请退款金额',

    -- AI 审核
    ai_audit_result     VARCHAR(256)    DEFAULT '' COMMENT 'AI审核结论',
    ai_confidence       DECIMAL(5,2)    DEFAULT 0.00 COMMENT 'AI置信度 0-100',
    ai_audit_status     TINYINT         NOT NULL DEFAULT 0 COMMENT 'AI审核状态：0待审核 1已办结 2待人工判定',
    ai_audit_time       DATETIME        DEFAULT NULL COMMENT 'AI审核完成时间',

    -- 工单状态
    ticket_status       TINYINT         NOT NULL DEFAULT 0 COMMENT '工单状态：0待AI审核 1AI已办结 2待人工审核 3已驳回 4已关闭',
    assignee            VARCHAR(64)     DEFAULT NULL COMMENT '指派人（客服），人工审核前指定负责人',
    manual_audit_by     VARCHAR(64)     DEFAULT '' COMMENT '人工审核人，实际执行审核操作的人',
    manual_audit_time   DATETIME        DEFAULT NULL COMMENT '人工审核时间',
    manual_remark       VARCHAR(1024)   DEFAULT '' COMMENT '人工备注',
    manual_result       TINYINT         DEFAULT NULL COMMENT '人工审核结果：1同意售后 2驳回售后',

    -- 链路追踪
    rag_rule_ids        VARCHAR(256)    DEFAULT '' COMMENT 'RAG召回规则ID列表，逗号分隔',
    mq_msg_id           VARCHAR(64)     DEFAULT '' COMMENT 'MQ消息ID（用于死信追踪）',
    retry_count         INT             NOT NULL DEFAULT 0 COMMENT 'MQ重试次数',

    created_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    UNIQUE KEY uk_ticket_no (ticket_no),
    KEY idx_order_no (order_no),
    KEY idx_store_id (store_id),
    KEY idx_user_id (user_id),
    KEY idx_ticket_status (ticket_status),
    KEY idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='售后工单表';
```

**字段设计要点：**
- `ticket_no` 工单号按 `SH + yyyyMMdd + 3位序列` 生成，便于按天检索
- `ai_audit_status` 与 `ticket_status` 分开：AI判定"待人工"后才进入人工流程
- `rag_rule_ids` 记录召回的规则ID列表，实现"可溯源"需求
- `retry_count` 配合 MQ 重试机制，超限后标记为死信

## 三、PgVector 向量库设计（RAG 核心）

PostgreSQL 只有一张表 `rag_vectors`，由 langchain4j 的 `PgVectorEmbeddingStore` 启动时自动创建，业务代码不直接操作。

```sql
-- PostgreSQL + pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE rag_vectors (
    id          UUID PRIMARY KEY,
    embedding   VECTOR(1024)    COMMENT '文本向量嵌入（dimension=1024，对应 text-embedding-v4）',
    text        TEXT            NOT NULL COMMENT '切片文本内容',
    metadata    JSONB           DEFAULT '{}' COMMENT '元数据，如 {"file_name": "03-服饰鞋包类售后规则.md"}'
);

-- IVFFlat 索引加速相似度检索
CREATE INDEX ON rag_vectors USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
```

## 四、Redis 缓存与数据结构设计

### 4.1 缓存 Key 规范

```
# 限流
rate:limit:token_bucket:{userId}    → Hash，令牌桶状态，包含tokens（当前剩余令牌）和lastRefill（上次补充令牌的时间戳）

# 缓存
cache:order:{orderNo}                → JSON String（订单信息，TTL 300s）
cache:store:{storeId}                → JSON String（店铺信息，TTL 600s）
cache:dashboard:stats                → JSON String（仪表盘统计，TTL 60s）
cache:config:all                     → Hash（全量配置，TTL 30s）

# 排行榜
rank:store:monthly:{yyyyMM}          → ZSet（店铺售后排名，score = 售后单数）
rank:store:monthly:202606            → ZSet member=storeId score=168

# 分布式锁
lock:order:audit:{ticketNo}          → String（工单审核锁，TTL 30s）
lock:doc:parse:{docId}               → String（文档解析锁，TTL 120s）

# 布隆过滤器（缓存穿透防护）
bloom:order_no                       → Bloom Filter
```

### 4.2 Redis 排行榜维护时机

| 触发时机 | 操作 |
|---|---|
| 工单创建成功 | `ZINCRBY rank:store:monthly:202606 {storeId} 1` |
| 工单被驳回 | `ZINCRBY rank:store:monthly:202606 {storeId} -1` |
| 月度结算完成 | `ZREM` 清理上月数据 |

## 五、MQ 消息结构设计

### 5.1 交换机与队列

| 交换机 | 类型 | 队列 | 路由键 | 消费者 |
|---|---|---|---|---|
| `exchange.after.sale` | topic | `queue.refund.only` | `refund.only.*` | AI审核 |
| `exchange.after.sale` | topic | `queue.refund.return` | `refund.return.*` | AI审核 |

## 七、建表顺序（依赖关系）

1. `store_info` / `order_info` （无外部依赖）
2. `after_sale_order`（依赖 store_info, order_info）
3. `ai_audit_log`（依赖 after_sale_order）
4. `dead_letter_message`（依赖 after_sale_order）
5. `reminder_log`（依赖 after_sale_order）
6. `system_config` / `operation_log`（无业务依赖）
7. `knowledge_doc`（独立，用于知识库管理）
8. `rag_vectors`（PgVector，由 langchain4j 自动管理）
