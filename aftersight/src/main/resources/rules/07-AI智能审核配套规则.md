# 三、AI智能审核配套规则文档（RAG专用）

## 3.1 AI审核总体流程

### 3.1.1 审核输入
AI审核消费者提交的售后申请时，需要接收以下信息：
1. 工单信息：ticketNo, orderNo, afterSaleType
2. 订单信息：productName, productSpec, payAmount
3. 售后信息：applyReason, evidenceImages
4. 店铺信息：storeName, storeCategory
5. 用户信息：userId, userLevel（可选）

### 3.1.2 审核输出格式
AI审核后应返回结构化JSON结果：

```json
{
  "conclusion": "同意/驳回/待人工",
  "confidence": 85.0,
  "reason": "审核理由说明",
  "suggestedAction": "建议处理方式",
  "applicableRules": ["引用的规则条款"],
  "riskFlags": ["风险标记"]
}
```

### 3.1.3 判定规则
| 置信度范围 | 处理方式 |
|-----------|---------|
| confidence ≥ 85 | AI自动办结（同意或驳回） |
| 60 ≤ confidence < 85 | 转人工审核（PENDING_MANUAL） |
| confidence < 60 | 转人工审核（标记为低置信度） |

## 3.2 RAG检索策略

### 3.2.1 检索触发条件
- 消费者提交售后申请后，系统自动触发AI审核
- 系统根据 `applyReason` 生成 query embedding
- 从知识库检索Top-N条最相关规则（默认N=5）

### 3.2.2 检索范围
| 检索源 | 优先级 | 说明 |
|-------|-------|------|
| 平台通用规则 | 高 | 所有品类通用的售后规则 |
| 品类专项规则 | 高 | 根据商品品类匹配对应的专项规则 |
| 优质判例 | 中 | 历史人工审核中标记为优质的判例 |
| 特殊场景规则 | 中 | 特殊场景下的处理规则 |

### 3.2.3 相似度阈值
- 检索结果相似度 < 60% 的不纳入参考
- 60%-75% 的作为辅助参考
- ≥ 75% 的作为主要依据

【商品品类】：{category_name}
【参考规则】：

## 3.4 置信度评估模型

### 3.4.1 正向信号（提高置信度）
| 信号 | 权重 |
|-----|------|
| 检索到的规则与申请原因高度匹配（sim ≥ 85%） | +15 |
| 有明确的品类专项规则可供引用 | +10 |
| 有相似判例支持（sim ≥ 80%） | +8 |
| 消费者举证材料完整清晰 | +5 |
| 申请金额较小（≤ 100元） | +3 |

### 3.4.2 负向信号（降低置信度/转人工）
| 信号 | 影响 |
|-----|------|
| 检索到的规则不匹配 | 置信度上限80% |
| 涉及负面信号申诉 | 必须转人工 |
| 消费者多次售后（投诉历史） | 降20% |
| 申请金额较大（≥ 5000元） | 降15% |
| 售后类型为投诉（complaint） | 降10% |
| 缺乏关键举证材料 | 降10% |
| 商品品类模糊（无法匹配专项规则） | 转人工 |

### 3.4.3 必须转人工的场景
1. 消费者声明"未收到货"或"物流异常"
2. 涉及人身伤害或安全事故
3. 消费者投诉商家存在欺诈行为
4. 申请金额超过5000元
5. 消费者明确要求"升级处理"或"投诉平台"
6. 相同订单重复提交售后申请
7. 涉及第三方平台责任（物流、支付等）

## 3.5 规则优先级

```
法律强制规定（《消费者权益保护法》等） > 
平台通用规则 > 
品类专项规则 > 
商家自定义规则 > 
优质判例参考
```

- 法律强制规定不可通过商家约定排除
- 商家承诺优于平台规则的，以更优者为准
- 商家承诺劣于平台规则的，以平台规则为准

## 3.6 多轮审核与申诉

### 3.6.1 AI审核不通过后的流程
1. AI审核驳回（confidence ≥ 85）
2. 消费者可发起人工申诉
3. 人工审核员复核AI结论
4. 若人工审核维持原判，消费者可再次申诉（升级处理）

### 3.6.2 AI审核与人工审核的冲突处理
- 人工审核有权推翻AI审核结论
- 每次推翻应记录原因，作为判例数据反馈给模型优化
- 同一商家/同一消费者的历史判例可作为参考
