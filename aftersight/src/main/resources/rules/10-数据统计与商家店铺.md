# 六、数据统计&商家店铺售后文档

## 6.1 数据统计规则

### 6.1.1 核心指标定义

**工单流转指标：**
| 指标 | 定义 | 计算公式 |
|-----|------|---------|
| 日新增工单数 | 当日创建的售后工单总数 | COUNT(ticket_no) WHERE DATE(created_at) = TODAY |
| AI处理数 | AI自动办结的工单数 | COUNT WHERE ai_audit_status = 1 |
| 人工介入数 | 需要人工审核的工单数 | COUNT WHERE ticket_status = 2 |
| AI通过率 | AI自动办结占比 | AI办结数 / 总处理数 × 100% |
| 待处理量 | 当前待人工审核的工单数 | COUNT WHERE ticket_status = 2 |

**时效指标：**
| 指标 | 定义 |
|-----|------|
| AI审核平均耗时 | AI从收到消息到完成审核的平均时长 |
| 人工审核平均耗时 | 工单从提交到人工审核完成的平均时长 |
| 消费者等待时长 | 工单创建到最终办结的总时长 |

**质量指标：**
| 指标 | 定义 |
|-----|------|
| AI审核准确率 | AI审核结果与人工复核结果一致的比例 |
| 申诉率 | 消费者对审核结果发起申诉的比例 |
| 申诉维持率 | 申诉后维持原判的比例 |

### 6.1.2 环比计算
- 环比增长率 = (今日值 - 昨日值) / |昨日值| × 100%
- 昨日值为0时，今日值 > 0 计为 +100%，今日值 = 0 计为 0%
- 保留两位小数

### 6.1.3 趋势分析
- 近7日趋势图：按日期展示每日新增、AI办结、待人工数量
- 月度趋势图：按天展示全月数据分布
- 同比对比：与上月同期数据对比

## 6.2 报表生成规则

### 6.2.1 日报
- 生成时间：每日凌晨 00:30
- 统计范围：前一日 00:00:00 - 23:59:59
- 包含：新增工单、AI处理、人工介入、通过率、峰值时段
- 发送对象：运营团队

### 6.2.2 月报
- 生成时间：每月1日 01:00
- 统计范围：上月全月
- 包含：月度总览、品类分布、店铺排行、趋势分析
- 支持导出Excel格式

### 6.2.3 实时看板
- 看板数据缓存：Redis缓存60秒
- 店铺排行缓存：10分钟（用ZSet存储）
- 看板数据在每次人工审核后刷新缓存

## 6.3 店铺售后管理

### 6.3.1 店铺评级
根据店铺的售后数据对店铺进行评级：

| 等级 | 评分区间 | 权益 |
|-----|---------|------|
| A级（优秀） | 售后率 < 1%, 响应率 > 99% | 优先审核、快速退款 |
| B级（良好） | 售后率 1%-3%, 响应率 > 95% | 正常审核 |
| C级（一般） | 售后率 3%-5%, 响应率 > 90% | 加强监控 |
| D级（待改进） | 售后率 > 5% 或 响应率 < 90% | 限制权益、重点监控 |

**售后率 = 售后工单数 / 订单总数 × 100%**
**响应率 = 商家在规定时间内响应售后的比例**

### 6.3.2 店铺排行
- 排行榜按月统计
- 统计维度：店铺售后工单数量
- 排序方式：按售后工单数降序排列
- 展示前10名店铺
- 支持导出排行榜数据

### 6.3.3 店铺售后类型分布
- 按店铺统计不同售后类型的分布
- 仅退款、退货退款、投诉的比例
- 帮助运营团队识别高售后风险店铺

## 6.4 售后类型占比分析

### 6.4.1 全平台售后类型分布
- 统计周期内各售后类型的数量及占比
- 计算方式：各类型数量 / 总售后数量 × 100%
- 展示格式：保留一位小数

## 6.5 AI审核数据反馈

### 6.5.1 AI审核表现追踪
- 按日追踪AI审核的准确率、覆盖率
- 按品类追踪AI审核的表现差异
- 识别AI审核表现较差的品类，进行规则优化

### 6.5.2 规则有效性分析
- 统计各规则在AI审核中的引用频率
- 统计引用规则的审核准确率
- 对准确率低的规则进行修订建议

### 6.5.3 判例效用追踪
- 追踪优质判例在AI审核中的引用次数
- 追踪引用判例的审核准确率
- 定期清理低效判例
