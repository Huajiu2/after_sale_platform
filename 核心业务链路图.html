电商智能售后中台 · 核心业务链路
示意 · 依据真实代码绘制（AfterSaleServiceImpl / MqProducer / AiAuditConsumer / RagConfig）
校验 / 数据库 Redis 中间件 文件 / 消息队列 AI / RAG 链路 人工处理
① 用户提交售后申请（POST /api/after-sale/submit · multipart）
1 校验订单号非空 → 2. Redisson 布隆过滤器 contains（bloom:order_no，100万容量 / 3%误判）拦截不存在的订单
↓
2 MySQL 查订单（order_info 联表 store_info）确认订单真实存在
↓
3 Redis 令牌桶限流（Lua 脚本原子执行，key=rate:limit:token_bucket:{userId}，容量5 / 每60秒补1令牌）→ 超限返回 429
↓
4 凭证图片上传 阿里云 OSS，返回 URL 列表存 JSON
↓
5 生成工单号 SH + yyyyMMdd + 3位序号（Redis INCR ticket:seq:{date}）
↓
6 落库 after_sale_order（ai_audit_status=0 待AI审核，ticket_status=0）→ 立即返回「提交成功，30秒内出结果」
↓
7 投递 RabbitMQ（Topic 交换机 exchange.after.sale），按售后类型选路由键
仅退款
routing key: refund.only.created
→ queue.refund.only
退货退款
routing key: refund.return.created
→ queue.refund.return
投诉
routing key: complaint.created
→ queue.complaint
↓ 异步消费（削峰填谷，接口已返回）
② AI 审核（AiAuditConsumer · RabbitListener 消费）
1 RAG 检索：申请原因 embedding 化 → PgVector 余弦检索（minScore=0.75，取前5条规则，正文带【文件名】溯源）
↓
2 组装提示词：订单信息 + 申请原因 + 参考规则；系统提示词 system-prompt.txt（角色/审核步骤/JSON强约束输出/few-shot）
↓
3 调用 DeepSeek（LangChain4j AiService）→ 解析结构化 JSON：conclusion / confidence / reason / applicableRules / suggestedAction / riskFlags
↓
4 写 ai_audit_log（prompt / response / 耗时 / 召回文档）→ 置信度分级裁决
confidence ≥ 85
ticket_status=1 AI 自动办结
（终态，无需人工）
confidence < 85
ticket_status=2 待人工审核
（人工兜底）
↓ 仅低置信度工单进入
③ 人工审核（manualAuditSubmit · 状态机）
关键 SQL：UPDATE after_sale_order SET ... WHERE ticket_no=? AND ticket_status=2 —— 状态校验 + 更新合并为一条原子 UPDATE，防并发重复处理
manualResult=1
同意 → 办结（status=1）
manualResult=0
驳回 → 已驳回（status=3）
善后
写 operation_log + 删除统计/排行 Redis 缓存
0 待AI审核 → 1 AI办结 / 2 待人工 → 3 已驳回
④ 配套链路（记忆要点）
知识库 RAG 入库：上传(md/pdf/doc/txt ≤20MB) → MQ解析队列 → 段落切片(1600/200) → embedding(text-embedding-v4, 1024维) → PgVector
死信链路：queue.doc.parse 绑 DLX → exchange.dlx / doc.parse.dlq → 死信落库 dead_letter_message → 运维重试/删除
